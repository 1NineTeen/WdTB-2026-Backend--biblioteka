Roadmapa laboratoriów

Każde laboratorium dokłada jedną warstwę backendu, a reguły projektu rosną razem z kodem. Laboratoria 01–02 są rozpisane szczegółowo. Pozostałe opisują zakres i wymagania; instrukcje pojawią się przed zajęciami. Liczby (ile tabel, zapytań, endpointów): WYMAGANIA.md. Zaliczenie, obecności i kryteria ocen: ZASADY.md. Pracujemy na zajęciach; kryteria oceny prowadzący podaje zawsze na początku zajęć.

LAB 01 · Start (bez oceny)

→ instrukcja LAB 01

  • wprowadzenie: backend, baza danych, architektura warstwowa (strona główna)
  • zespół 3-osobowy, fork szablonu na GitHubie przemianowany na WdTB-2026-Backend-<nazwaprojektu>, wpis w arkuszu grupy
  • uruchomienie aplikacji: strona startowa, konsola H2, zapytania SQL, pierwsze zmiany (konto w data.sql, port, nazwa projektu)
  • pomysł: persona, historyjki, wstępny model danych
  • opis projektu: PROJEKT.md i wizytówka na stronie startowej, 2-minutowa prezentacja
  • Reguły: R1.01–R1.05

LAB 02 · Encje i relacje

→ instrukcja LAB 02

  • encje JPA: @Entity, @Table, @Id, @GeneratedValue, @Column, @Enumerated
  • relacje: @ManyToOne, @OneToMany(mappedBy), @ManyToMany / encja łącząca, @OneToOne, powiązanie z user_account
  • typy: BigDecimal dla kwot, enumy jako tekst, daty
  • konsola H2: czytanie DDL wygenerowanego przez Hibernate
  • dane startowe w data.sql
  • Reguły: R2.01–R2.10, sprawdzane tylko na schemacie bazy i danych

LAB 03 · Repozytoria i zapytania

  • pierwsze reguły ArchUnit: higiena encji (LAZY, STRING, konstruktor, @Embeddable)
  • Spring Data JPA: zapytania pochodne, @Query (JPQL), GROUP BY, projekcje, Pageable
  • problem N+1: QueryCounter, @EntityGraph, JOIN FETCH
  • „pytania inwestora” i testy @DataJpaTest
  • Reguły: R3.01–R3.16

LAB 04 · Serwisy i komponenty

  • kontener IoC: @Component, @Service, @Configuration + @Bean, wstrzykiwanie przez konstruktor, cykl życia i zasięg beana
  • warstwa application: przypadki użycia, @Transactional (propagacja, readOnly, rollback)
  • reguły biznesowe w kodzie i wyjątki domenowe
  • moduły: pakiet api jako publiczny kontrakt modułu; relacje encji między modułami zastępujemy identyfikatorami
  • testy jednostkowe z Mockito, testy parametryzowane
  • Reguły: R4.01–R4.09

LAB 05 · Kontrolery REST

  • @RestController, mapowania HTTP, ResponseEntity, kody odpowiedzi, nagłówek Location
  • DTO jako rekordy, mapowanie encja ↔ DTO
  • Bean Validation (@Valid, @NotBlank, @Future), @RestControllerAdvice + ProblemDetail
  • stronicowanie i filtrowanie w API, endpointy raportowe z pytaniami inwestora
  • OpenAPI / Swagger UI (springdoc), pliki .http w IntelliJ
  • @WebMvcTest + MockMvc
  • Reguły: R5.01–R5.08

LAB 06 · Rozbudowa

  • zdarzenia aplikacyjne: ApplicationEventPublisher, rekordy *Event, @TransactionalEventListener
  • konfiguracja: @ConfigurationProperties jako rekord, profile
  • @Scheduled: wygaszanie rezerwacji, przypomnienia, raport dnia
  • wyzwanie 5.0: integracja z API innego zespołu przez RestClient w infrastructure, z testem MockRestServiceServer
  • Reguły: R6.01–R6.04

LAB 07 · Odrabianie

  • nadrobienie niezaliczonego materiału (nieobecności, oceny niedostateczne)
  • poprawa czerwonych labów zespołu
  • zespoły bez zaległości: krótka prezentacja projektu i wyzwania 5.0 podnoszące ocenę
