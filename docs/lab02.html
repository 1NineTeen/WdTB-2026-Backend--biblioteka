TeoriaB · Wprowadzenie: tabela ↔ encja, typy kolumn, relacja

B1. Encja to klasa, która opisuje tabelę

Na LAB 01 widzieliście w oknie Run polecenie create table user_account. Hibernate wygenerował je z klasy UserAccount. Tak działa JPA: klasa ↔ tabela, pole ↔ kolumna, obiekt ↔ wiersz. Otwórzcie account/domain/UserAccount.java i porównajcie z tabelą w konsoli H2:

Adnotacja Znaczenie W UserAccount
@Entity klasa jest encją: Hibernate tworzy dla niej tabelę nad klasą
@Table(name = "…") nazwa tabeli w bazie (małe litery, podkreślenia) user_account
@Id + @GeneratedValue(strategy = IDENTITY) klucz główny; numer nadaje baza (1, 2, 3…) Long id
@Column(name, nullable, unique, length) nazwa i ograniczenia kolumny email: wymagany, unikalny, 120 znaków
@Enumerated(EnumType.STRING) enum zapisany jako tekst ('ADMIN'), a nie numer pozycji AccountRole role
konstruktor protected bez argumentów wymaga go Hibernate; drugi, publiczny, służy Wam protected UserAccount() {}

B2. Typy kolumn

Dane Typ pola w Javie Uwagi
tekst String zawsze z length, np. 60 lub 120
liczby całkowite, ilości Integer, Long liczba miejsc, sztuk, punktów
kwoty, ceny, oceny dziesiętne BigDecimal nigdy double ani float: 0.1 + 0.2 daje 0.30000000000000004; kolumna precision = 10, scale = 2
data, data z godziną LocalDate, LocalDateTime w data.sql: '2026-11-14', '2026-11-14 18:00:00'
status, typ, kategoria ze stałej listy enum zawsze z @Enumerated(EnumType.STRING)
tak / nie Boolean np. active

B3. Pokaz: relacja jednokierunkowa

Tego kroku nie wykonujecie w swoim projekcie: to pokaz, jak tabele łączą się ze sobą. Relacje dodacie na kolejnych zajęciach.

W kawiarni rezerwacja dotyczy jednego stolika, a przy jednym stoliku może być wiele rezerwacji. W bazie zapisuje to klucz obcy: kolumna reservation.table_id wskazuje wiersz w tabeli cafe_table.

cafe_table                     reservation
+----+--------+-------+        +----+---------------------+----------+
| id | number | seats |        | id | starts_at           | table_id |
+----+--------+-------+        +----+---------------------+----------+
|  1 |      1 |     2 | <------|  2 | 2026-11-15 12:30:00 |        1 |
|  2 |      2 |     4 | <------|  1 | 2026-11-14 18:00:00 |        2 |
+----+--------+-------+        +----+---------------------+----------+

W JPA kolumnę klucza obcego opisuje pole typu drugiej encji. Stolik jest zwykłą encją bez relacji:

@Entity
@Table(name = "cafe_table")
public class CafeTable {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "number", nullable = false, unique = true)
    private Integer number;

    @Column(name = "seats", nullable = false)
    private Integer seats;

    @Column(name = "room", nullable = false, length = 40)
    private String room;

    protected CafeTable() {
    }
}

Rezerwacja ma pole table typu CafeTable:

@Entity
@Table(name = "reservation")
public class Reservation {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "starts_at", nullable = false)
    private LocalDateTime startsAt;

    @Column(name = "party_size", nullable = false)
    private Integer partySize;

    // wiele rezerwacji → jeden stolik; table_id to kolumna klucza obcego
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "table_id", nullable = false)
    private CafeTable table;

    protected Reservation() {
    }
}

Hibernate generuje z tego kolumnę table_id i klucz obcy:

create table reservation (
    party_size integer not null,
    id bigint generated by default as identity,
    starts_at timestamp(6) not null,
    table_id bigint not null,
    primary key (id)
)

alter table if exists reservation
   add constraint FKs87ss6lovy66qn86ra7rbc8e1
   foreign key (table_id)
   references cafe_table

W data.sql najpierw wstawia się stoliki, potem rezerwacje z numerem id stolika:

insert into cafe_table (number, seats, room) values
    (1, 2, 'sala główna'),
    (2, 4, 'sala główna');

insert into reservation (starts_at, party_size, table_id) values
    ('2026-11-14 18:00:00', 4, 2),
    ('2026-11-15 12:30:00', 2, 1);

W konsoli H2 obie tabele łączy zapytanie z join po kluczu obcym:

select r.starts_at, r.party_size, t.number as table_no, t.room
from reservation r
join cafe_table t on t.id = r.table_id;
Element Znaczenie
@ManyToOne wiele rezerwacji wskazuje na jeden stolik; adnotacja stoi po stronie „wiele”
@JoinColumn(name = "table_id") nazwa kolumny klucza obcego w tabeli reservation
fetch = FetchType.LAZY stolik jest doczytywany z bazy dopiero wtedy, gdy kod go użyje
jednokierunkowa rezerwacja zna swój stolik, a w klasie CafeTable nie ma nic o rezerwacjach; w bazie to wystarcza

ZadanieE · Encje w kodzie: krok po kroku

Przykład prowadzi kawiarnię z LAB 01: stolik, pozycja menu i gość. Wy wpisujecie swoje nazwy tabel i kolumn; nazwy klas, pól i pakietów po angielsku, jak w UserAccount. Po każdej encji uruchamiacie aplikację (Rerun w oknie Run) i czytacie w logu polecenie create table. Czerwona adnotacja: Alt+Enter → Import class (pakiet jakarta.persistence).

E1. Pakiety modułów

Prawy przycisk na pakiecie pl.wsb.<projekt> → New → Package → wpiszcie seating.domain (IntelliJ utworzy oba poziomy). Tak samo menu.domain i guest.domain. Encje i enumy leżą w pakietach <moduł>.domain (R2.02).

E2. Pierwsza encja: stolik

Prawy przycisk na seating.domain → New → Java Class → CafeTable (nazwa Table jest zajęta przez adnotację JPA):

package pl.wsb.kawiarnia.seating.domain;

import jakarta.persistence.*;

@Entity
@Table(name = "cafe_table")
public class CafeTable {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "number", nullable = false, unique = true)
    private Integer number;

    @Column(name = "seats", nullable = false)
    private Integer seats;

    @Column(name = "room", nullable = false, length = 40)
    private String room;

    protected CafeTable() {
    }

    public CafeTable(Integer number, Integer seats, String room) {
        this.number = number;
        this.seats = seats;
        this.room = room;
    }

    // gettery: Code → Generate… → Getter → zaznaczcie wszystkie pola
}

Konstruktor i gettery generuje IntelliJ: Code → Generate… (macOS ⌘N, Windows Alt+Insert). Setterów nie generujcie. Po Rerun w logu pojawia się:

create table cafe_table (
    number integer not null unique,
    seats integer not null,
    id bigint generated by default as identity,
    room varchar(40) not null,
    primary key (id)
)

E3. Druga encja: pozycja menu (enum i kwota)

Najpierw enum: prawy przycisk na menu.domain → New → Java Class → Enum → MenuCategory:

package pl.wsb.kawiarnia.menu.domain;

public enum MenuCategory {
    COFFEE, TEA, CAKE
}

Potem encja MenuItem w menu.domain:

@Entity
@Table(name = "menu_item")
public class MenuItem {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false, unique = true, length = 60)
    private String name;

    @Enumerated(EnumType.STRING)
    @Column(name = "category", nullable = false, length = 20)
    private MenuCategory category;

    @Column(name = "price", nullable = false, precision = 10, scale = 2)
    private BigDecimal price;

    @Column(name = "available", nullable = false)
    private Boolean available;

    protected MenuItem() {
    }

    // konstruktor z polami i gettery: Code → Generate…
}

W logu enum jest tekstem, a cena liczbą z dwoma miejscami po przecinku. Z double byłoby float(53), czyli zaokrąglenia przy każdym dodawaniu (R2.04):

create table menu_item (
    available boolean not null,
    price numeric(10,2) not null,
    id bigint generated by default as identity,
    name varchar(60) not null unique,
    category enum ('CAKE','COFFEE','TEA') not null,
    primary key (id)
)

ZadanieF · Dane startowe i konsola H2

F1. data.sql

Hibernate tworzy tabele od nowa przy każdym starcie, a potem Spring Boot wykonuje src/main/resources/data.sql. Dane każdej tabeli wpisujecie w jej sekcji (C3) na końcu pliku, pod kontami z LAB 01. Zasady:

  • Bez id: baza numeruje wiersze sama, od 1.
  • Nazwy kolumn dokładnie jak w @Column(name); enumy jako tekst w apostrofach ('COFFEE'); daty jako '2026-10-01'; kwoty z kropką (9.00).
  • 2–3 wiersze na tabelę, sensowne dla Waszego pomysłu. Reguła R2.05 wymaga co najmniej jednego w każdej tabeli.

F2. Sprawdzenie w konsoli H2

Po Rerun otwórzcie http://localhost:8080/h2-console (JDBC URL jdbc:h2:file:./data/wdtb, użytkownik sa, hasło puste). Po lewej stronie jest lista tabel: rozwińcie każdą swoją tabelę i sprawdźcie kolumny. Potem dla każdej tabeli wykonajcie select i porównajcie wiersze z data.sql:

select * from cafe_table;
select * from menu_item;
select * from guest;

select name, price from menu_item where category = 'COFFEE' order by price;

Każda tabela ma pokazać tyle wierszy, ile wpisaliście. Pusta tabela oznacza brak sekcji w data.sql albo literówkę w nazwie tabeli.

F3. Typowe błędy przy starcie

Komunikat w logu Przyczyna i poprawka
Column "…" not found nazwa kolumny w insert różni się od @Column(name)
Table "…" not found klasa bez @Entity albo poza pakietem pl.wsb.<projekt>; inna nazwa w @Table(name)
NULL not allowed for column "…" kolumna z nullable = false pominięta w insert
Unique index or primary key violation dwa wiersze z tą samą wartością kolumny unique (np. numer stolika, nazwa pozycji menu)
No default constructor for entity brak konstruktora protected <Klasa>() {}
Port 8080 was already in use poprzednie uruchomienie wciąż działa: czerwony kwadrat w oknie Run

Błąd w data.sql zatrzymuje start aplikacji, więc czerwone są też R1.02 i R2.05. Czytajcie log od pierwszej linii z Caused by: tam jest nazwa tabeli i kolumny.

ZadanieG · Reguły, commit, tag lab-2

  1. Reguły lokalnie: panel Maven (prawa krawędź okna) → Lifecycle → dwuklik na verify. W oknie Run przy każdej regule R2.xx jest zielony albo czerwony znak, a przy czerwonej opis, co poprawić. Poprawiacie, aż LAB 01 i LAB 02 są zielone.
  2. Ostatnie zmiany: Commit z opisem (np. „Poprawki po regułach LAB 02”), Push. Na GitHubie zakładka Actions: przebieg „Testy i reguły” ma być zielony.
  3. Tag lab-2 (gdy wszystkie zmiany są na GitHubie): okno Git → zakładka Log → prawy przycisk na ostatnim commicie → New Tag… → nazwa lab-2. Potem Git → Push i w oknie zaznaczcie Push Tags. W Actions pojawi się przebieg dla tagu: to stan, który ocenia prowadzący.
  4. Wizytówka: w static/index.html dopiszcie do listy zmian, co powstało na LAB 02 (nazwy tabel). Od tego zaczniecie prezentację na kolejnych zajęciach.

Prowadzący ocenia ze stanu na tagu: zielone reguły (warunek konieczny), zgodność tabel z pomysłem z wizytówki, sensowne dane startowe i rozmowę: każda osoba potrafi wyjaśnić dowolną encję zespołu, nie tylko własną.
