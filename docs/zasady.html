Zasady zaliczenia

Pracujemy na zajęciach

  • Zadania z danego laboratorium wykonujecie na zajęciach, nie w domu.
  • Kryteria oceny prowadzący podaje zawsze na początku zajęć. Tabela niżej to plan, który może się zmienić.
  • Ocenę wystawia prowadzący na koniec zajęć, ze stanu repozytorium na tagu lab-N zrobionym w trakcie zajęć.
  • Czego nie skończycie na zajęciach, nadrabiacie na ostatnich zajęciach (LAB 07).

Obecność

  • Przychodzicie na zajęcia swojej grupy.
  • Wyjątkowo można przyjść na zajęcia grupy wcześniejszej lub późniejszej, o ile jest wolne miejsce. Zapytajcie prowadzącego przed zajęciami.
  • Jedna nieobecność jest dopuszczalna bez konsekwencji. Materiał z tych zajęć nadrabiacie z zespołem.
  • Każda kolejna nieobecność oznacza niezaliczony materiał z tych zajęć. Można go odrobić na ostatnich zajęciach (LAB 07).

Odrabianie: LAB 07

Ostatnie zajęcia służą do nadrobienia zaległości:

  • osoby z niezaliczonym materiałem (nieobecność, ocena niedostateczna) zaliczają brakujący lab,
  • zespoły poprawiają niezaliczone laby na miejscu (stan oceniany z nowego tagu, np. lab-3-poprawa),
  • zespoły bez zaległości mogą pokazać projekt i podnieść ocenę wyzwaniami 5.0.

Ocena z laboratorium

  • LAB 01 nie jest oceniany (konfiguracja i szkic pomysłu).
  • Oceniane są laby 02–06. Ocena z laboratorium to średnia z tych pięciu ocen.
  • Każdy lab oceniany jest ze stanu repozytorium na tagu lab-N: zielone „Testy i reguły” to warunek konieczny (3.0).

Kryteria oceny laboratoriów (plan)

Lab 3.0 4.0 5.0
01 bez oceny
02 · Encje i relacje zielone reguły R1–R2, tag lab-2 5–6 tabel, ≥2 relacje 1:N, encja łącząca z atrybutami, dane w data.sql; każda osoba ma Pull Request z encją wyzwanie (np. @Embeddable, audyt, equals/hashCode) + pytania kontrolne
03 · Repozytoria i zapytania zielone reguły R1–R3, tag lab-3 5 pytań inwestora, każde z metodą i testem; każda osoba ma Pull Request z zapytaniem wyzwanie (np. Specification, test N+1 „przed/po”) + pytania kontrolne
04 · Serwisy i komponenty zielone reguły R1–R4, tag lab-4 ≥3 reguły biznesowe z wyjątkami i testami; każda osoba ma Pull Request z serwisem wyzwanie (np. testy parametryzowane, Spring Modulith) + pytania kontrolne
05 · Kontrolery REST zielone reguły R1–R5, tag lab-5 2 zasoby z pełnym CRUD, endpoint raportowy, plik .http; każda osoba ma Pull Request z endpointem wyzwanie (np. własny walidator, stronicowanie i sortowanie w API) + pytania kontrolne
06 · Rozbudowa zielone reguły R1–R6, tag lab-6 zdarzenie i zadanie cykliczne z testami integracja z API innego zespołu + pytania kontrolne

Pytania kontrolne zadaje prowadzący losowej osobie z zespołu. - Ocena indywidualna: osoba bez własnego zmergowanego Pull Requesta na danym labie albo bez zrozumienia wskazanego fragmentu kodu zespołu dostaje za ten lab maksymalnie 3.0.
